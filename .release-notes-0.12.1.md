Sessions used by a scheduled task are marked as such (v0.12.1)

The tmux page now says which sessions belong to a scheduled task: a session a task keeps for itself
(`task-<name>`) and every per-run session a "new session for every run" task still keeps carry a
*scheduled* chip and the task's name, with whether it is the task's own session or one of its runs.

That turns an anonymous `task-nightly` in the list into "scheduled task nighty check (its own session)",
which matters when the only thing you know about a session is its name.

## Also

- `Engine.task_sessions(machine_id)` maps the sessions of the tasks on a machine to their task
  (`task_session`: its `tmux_name`; `new_session`: the sessions it keeps in `/data/tasks.json`). A task
  that never ran has no session, so nothing is marked for it.
- Docs: README tmux section, ARCHITECTURE 4.3, AGENTS.md hard-won facts.
- Tests: the runtime marks a task's session and leaves the others alone; `Engine.task_sessions` covers
  own sessions, per-run sessions, another machine's tasks and `agent`-target tasks.

Update: `docker compose pull && docker compose up -d` in the telerouter container (image `:0.12` /
`:latest`). Nothing changes on the machines.
