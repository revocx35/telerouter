## A voice request no longer answers "the MCP server is down" after an agent restart

telerouter issued a fresh MCP token every time it (re)started an agent's tmux session and wrote it into
`~/.hermes/config.yaml` on the agent host. A Hermes gateway that was already up keeps the token it read
until its next config check, so for a minute or two every MCP call from that agent got `401 Unauthorized`
— the answer on the speaker said the MCP server was unreachable while the server was perfectly healthy.
Seen today while asking for a call: "Call Batu" ×4, each answered with an MCP failure.

The agent's token is now issued once: a (re)start reads the plain token back from
`<dir>/mcp-token` on the agent host and reuses it while the stored hash still matches, and only mints a
new one when that copy is missing or stale. Regenerating a token stays an explicit action in the UI.

## Also

- `AgentRuntime._issue_mcp_token` is async now (it reads the host copy over SSH); the unit test covers
  both the reuse and the re-issue.
- Docs: AGENTS.md hard-won facts + ARCHITECTURE.md MCP row.

Update: `docker compose pull && docker compose up -d` in the telerouter container (image `:0.11` /
`:latest`). Agents restart with the same conversations; the token they already have stays valid.
