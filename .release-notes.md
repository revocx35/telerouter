## Hermes answers, not its terminal

A session on a Hermes machine was answered by watching its tmux pane until it went quiet. A TUI pane holds
the reasoning, the shell commands ("ran 1 command"), file edits, the status bar and, on a fresh session, the
skills banner — so scheduled tasks stored that as their result ("task completed", with the thinking block in
it) and speakers read the commands out loud. Hermes' own hook events carry the answer instead:

- **The turn's event is the answer.** Hermes hooks are global to the host's install, so the
  `events.jsonl` of any telerouter Hermes agent on that machine records *every* session's turns — task
  sessions and sessions the owner started by hand included. `post_llm_call` carries the turn's final
  response next to the prompt that started it, so telerouter takes the one with its own nonce (a small
  reader kept on the machine prints just the reply). Watching the pane is now only the fallback for hosts
  without those hooks.
- **A new Hermes session is left to draw first**: telerouter waits until the TUI stops changing before
  typing, so the prompt no longer lands in a booting screen (and the banner no longer comes back as an answer).
- **Big events are no longer dropped**: `post_llm_call` carries the whole conversation history (~1 MB), and
  past 1 MB telerouter used to ignore the line — a voice reply would time out as the conversation grew. The
  hook now trims that field (and appends the line untouched if it cannot), and the reader's line limit is 8 MB.
- Tests: the reply comes from the event and never from the pane, the fallback when a host has no hooks, the
  reader picking the right turn by nonce, a new Hermes session settling before typing, and the hook trimming
  (plus keeping a line it cannot parse). Verified against the real Hermes install on CT 123: a turn that ran
  a command returned "4" from the event in 4 s while its pane showed "ran 1 command" and the status bar.
- `ARCHITECTURE.md` (§4.1) and `AGENTS.md` updated.
